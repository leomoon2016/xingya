2. 固定的技能版本必须是已发布状态；回滚只能指向已发布版本。
3. 角色月度预算 ≤ 全站当月上限；参数覆盖只能使用技能 `default_params` 中已有的键且类型一致。
4. 儿童技能的输出模式必须是 `{reply: string}`；工具不得接受任何 ID 参数。
5. 工具名不得为发布类（启动时断言）；导入包中的脚本没有执行路径（测试断言不创建子进程）。

这些已写入 `nfr.md` §10.2 与 `03-design/modules/agents.md` 测试要点。

### D. 建议
1. W5–6 先实现工具目录、提示词组装与执行器的测试（含“第 21 步强制结束”“输出校验失败无副作用”“孩子工具不能读别的孩子”），再接各业务工具。
2. 导入功能上线前用恶意 ZIP（路径穿越、符号链接、超大、压缩炸弹、带 shebang 的脚本）做一次专项测试，与资料上传的专项测试合并进行。
3. 首发只有一个家庭时，运营分析师的价值有限；若进度紧张，可只保留其“任务与费用汇总”工具（不影响削减顺序中的不可削减项）。
4. 每次修改默认技能（`content/skills/`）都在 CI 中跑儿童安全测试集；呀哈哈队长的每个新技能版本在发布前人工试聊一轮。
