## 0. 术语

权威术语表见根目录 [GLOSSARY.md](../../GLOSSARY.md)；本表与之冲突时以术语表为准。

| 术语 | 含义 |
| --- | --- |
| 家庭 | 租户根。所有**家庭数据**都带 `family_id`；全站共享的目录表（词库与课程、工作室、技能与 AI 角色、伙伴与呀哈哈家族目录、商店）没有（见[数据模型 §6.2](../03-design/data-model.md#62-租户隔离)）。一个家庭有多个家长和多个孩子 |
| 家长 | 家庭内的管理者，邮箱 + 密码登录；同一家庭的家长权限相同 |
| 孩子 | 家长添加的学习者档案，昵称 + 头像 + 年级 + 4 位 PIN，可选用户名/密码 |
| 系统管理员 | 运维账号，不属于任何家庭；只处理举报、异常与系统设置 |
| 家庭设备 | 家长登录后标记为“家庭设备”的浏览器；此后显示头像墙，孩子点头像输 PIN 进入 |
| 课程版本 | 课程的一次发布。课程存放在数据库，草稿 → 审核 → 发布；已发布版本不可修改，再编辑会产生新版本 |
| 年级 > 课程 > 单元 > 关卡 > 题目 | 内容层级（[ADR 0016](../adr/0016-unit-layer.md)）。**课程** = 一册（如一年级上册 `en-g1-a`），发布与版本以课程为单位，课程版本包含全部单元；**单元** = 围绕一个主题的一组关卡（如 Unit 3 Animals），每单元 3–6 关（`已默认，可调整`，Q26），单元在课程内、关卡在单元内按顺序解锁。课程 ID、单元（`unit_key`，如 `u03`）、关卡（`level_key`，单元内唯一）、题目（`question_key`）有跨版本稳定键 |
| 词库 / 义项 | 全站共享的词（`en.apple`）与义项（`en.bat.animal`）；复习进度绑定义项 |
| 课程模板 | 仓库中定义的课程结构（每个单元的关卡结构、题型组合、每关题数、适用年级），首发 4 个 |
| 作答（play） | 开始一关或一次复习时服务端创建的记录：只下发题目可见部分，逐题判分反馈，完成时结算 |
| 闯关记录（attempt） | 一次闯关作答完成后的结算记录（每次作答最多一条） |
| 复习条目 | 进入间隔复习队列的一个义项或一道错题，处于 1–6 盒之一 |
| 账本（ledger） | 只追加的账本，记录星星与碎片两种币种；余额由流水推导 |
| 星级 | 一次闯关的评分，1–3 星级；是评价，不是货币（1 个星级提升 = 发 1 颗星星） |
| 星星 | 孩子可以花的主要货币 |
| 学习星 | 来自通关、完成复习、连续学习里程碑的星星；只有它计入排行、伙伴经验、领养门槛 |
| 奖励星 | 不是学习得来的星星（呀哈哈家族发现奖励、家长奖励、收到赠送）；可以花，但不计入排行、伙伴经验和领养门槛 |
| 碎片 | 第二种货币，只从学习获得，只用于领养伙伴 |
| 伙伴 | 孩子领养到的一只原创小伙伴（伙伴模块 companion） |
| 跟随伙伴 | 孩子当前带在身边的那一只伙伴，同一时间只有一只；随学习星获得经验、成长换形象 |
| 呀哈哈队长 | AI 聊天助手（原创小树灵，固定形象）；也是唯一面向孩子的 AI 角色 |
| 呀哈哈家族 / 藏匿点 / 图鉴 | 可收集的小精灵款式；通关后关卡场景里打开 3 个藏匿点（内容由服务端决定）；找到的款式进入图鉴 |
| 投放规则 | 限时活动规则或课程设定规则，调整藏匿点概率、款式或必得；可由 AI 按固定结构填写 |
| AI 工作室 | 系统管理员使用的生成工具：任务队列、素材库、费用预估与月度预算；技能库与 AI 角色 |
| 技能（Skill） | 数据库中的版本化提示词包：何时使用、指令、输入输出模式、内置工具白名单、参考资料、推荐模型；没有可执行代码；兼容 SKILL.md 导入导出 |
| AI 角色 | 有名字与头像、挂载若干技能、限定工具与月度预算的 AI“员工”（课程设计师、美术设计师、配音师、活动策划、质检员、运营分析师、呀哈哈队长）；配置随版本保存 |
| 流水线 | 多个 AI 角色按顺序接力完成一项工作（如 课程设计师 → 美术设计师 → 配音师 → 质检员 → 系统管理员审核），每步显示进度与费用 |
| 本地日期 | 按家庭时区换算的日期；所有“每天”“每周”的规则都按本地日期计算 |
| 审核 | 系统管理员在发布课程、伙伴、呀哈哈家族款式、技能或 AI 角色之前做的检查 |
| 审批 | 家长对孩子的申请（兑换现实奖励、跨家庭好友等）做出同意或拒绝 |
| 客户端请求 ID | 每个写请求携带的 UUID（请求头 `X-Client-Request-Id`），用于幂等 |

## 1.1 背景
旧系统是为一个家庭（3 个孩子）逐步长出来的：同步 SQLite 风格业务层经 worker 桥接 MySQL、内容以 JSON 大字段入库并靠启动补丁升级、十几种奖励货币、错题“答对即移除”、管理员与家长两套账号、MySQL 对公网开放、使用第三方 IP 形象（详见 `/workspace/greenfield-review/01-现状功能清单与问题.md`，下称“评审报告”）。本次决定**从零设计**：保留被验证有用的功能意图，用更小、更可靠的结构重新实现。

## 1.2 用户明确说的 vs 本规格的假设

| 类别 | 用户明确决定（已确认） | 本规格据此补充的假设/细化（见 [§14.2](PRD.md) 汇总） |
| --- | --- | --- |
| 用户范围 | 先自己家庭，后开放给更多家庭；家庭为租户；首发 1 个家庭；无计费、无机构 | 注册先用“邀请码模式”，由系统管理员发码；以后切到开放注册只改一个设置 |
| 客户端 | 首发只有 Web（React 19 + Vite，可安装 PWA）；小程序和苹果应用以后复用同一 API | 会话令牌同时支持 Cookie 与 `Authorization: Bearer`，为以后客户端预留，首发只用 Cookie |
| 内容 | 首发只有英语（单词、发音、课程 > 单元 > 关卡）；学科是字段。**变更后**：课程存数据库并版本化（草稿 → 审核 → 发布，已发布不可改）；共享词库；题目分可见部分与答案部分；AI 生成课程（4 个模板；一次生成整门课程或单个单元） | 新学科只需新增内容和题型，数据库不改（`subject`/`type` 用受正则约束的 VARCHAR）；模板 ID 与默认值见 [开放问题](open-questions.md) |
| 架构 | 模块化单体：Node 24 + Fastify 5 + Kysely + Zod + mysql2；Nginx；MySQL 8.4 只监听本机，SSH 隧道管理；LLM 与邮件外部；1 台阿里云 ECS 2GB + swap；每晚备份 14 天 + OSS。**变更后**：素材在阿里云 OSS、经 CDN 提供；音频在发布时由后台任务以一次性进程运行 Piper 生成，不常驻语音服务；AI 任务队列在 MySQL，最多 2 个并发。**第 10 部分**：AI 由“角色 + 技能”执行，执行器在 studio 模块中（工具循环 ≤ 20 步、带超时），技能版本化存数据库、无可执行代码。**目录调整（ADR 0015）**：系统管理端是独立前端应用，部署在后台子域名，独立 CSP；孩子端不包含后台代码 | 应用与 SSH 隧道都经 Unix socket 连接 MySQL；仓库只保留模板定义与少量示例课程 |
| 学习 | 每关 5–8 题、≥80% 通过、1–3 星级、只发提升差额；间隔 1/2/4/7/15/30 天；每日最多 20 条。**变更后**：9 种题型；作答前只下发可见部分、选项每次打乱 | 跟读题不计分；星级阈值 100%/90%/80%；复习完成奖励 2 星；连续里程碑 3/7/20 星；逐题反馈只记第一次作答 |
| 星星、伙伴与社交 | 只追加流水；商店、原创形象；现实奖励冻结/批准；赠送每天 ≤20；周排行只算学习所得；跨家庭需双方家长确认。**变更后**：碎片为第二币种（同一账本）；伙伴（档位、营地、成长阶段、AI 设计）；呀哈哈发现（藏匿点、图鉴、投放规则、AI 填写规则） | 好友关系以“家庭”为单位，用好友码发起；全站榜只含开启跨家庭功能的家庭 |
| 账号 | 家庭为根；家长邮箱密码；孩子 PIN；家庭设备；PIN 5 次错锁 15 分钟；远程下线 | 系统管理员登录必须 TOTP；会话时长见 [§4.3.5](modules/family.md) |
| 管控与报告 | 每日时长、可用时段、30 秒心跳、服务端强制、+15 分钟；夜间汇总；周日 20:00 周报；审批收件箱；呀哈哈队长 20 条/天 | 默认 40 分钟/天、07:00–21:00；超时后已开始的作答有 10 分钟提交宽限 |
| 工程 | 客户端请求 ID 幂等；一个业务操作一个事务；账本靠 DB 授权只追加；设置乐观锁；离线只缓存外壳与当前课程素材；测试、部署、约 20.5 周排期（变更前 13 周，设计变更后 19 周，第 10 部分 +1.5 周）；ICP 备案是上线阻塞项（CDN 域名同样需要备案） | 幂等表只记成功结果；锁顺序约定见 [§4.5.2](nfr.md) |

### 14.2 本规格自行确定的细节（用户未逐字指定）
1. 跟读题不计分、不计入正确率；每关至少 4 道计分题；录音不上传。
2. 星级阈值 100% / ≥90% / ≥80%；1 个星级 = 1 颗星。
3. 当日复习完成奖励 2 星；连续里程碑 3/7/30 天奖励 3/7/20 星；“学习日”= 通过 ≥1 关或完成当日复习。
4. 复习：首次通过时整关词入队；答错的计分题入队；6 盒答对仍留 6 盒；义项类复习条目由服务端按种子确定性出题。
5. 时长默认 40 分钟、07:00–21:00、呀哈哈队长 20 条/天；提交有 10 分钟宽限；“+15 分钟”同时放宽时长与时段，每天最多 120 分钟。
6. 家长手动奖励只加不减（1–50/次）；每孩子最多 3 个待审批兑换；孩子可撤回。
7. 好友关系以家庭为单位，用好友码由家长发起、对方家长批准；全站榜只含开启跨家庭功能的家庭；退出排行的孩子不出现也不显示排行入口。
8. 家庭内消息包括孩子与家长之间；举报后消息对双方隐藏；孩子可屏蔽、只有家长可解除；每孩子每天 50 条消息。
9. 注册采用邀请码模式；系统管理员强制 TOTP；会话有效期见 [§4.3.5](modules/family.md)；一个邮箱只属于一个家庭。
10. （2026-10-21 起）课程存数据库并版本化；仓库 `seeds/`（原 `content/`，ADR 0015）只放内置数据：模板、示例课程、装扮初始数据、短语、安全词表、头像、默认技能与角色挂载；词文本与义项释义不可修改，勘误 = 退役旧义项并新建。
11. 幂等：通用幂等表（只存成功响应）+ 业务唯一键；心跳与聊天例外。
12. 数据库账号只建 `@localhost`，应用与隧道都走 Unix socket；账号初始锁定、口令由引导脚本设置。
13. 备份 OSS 副本用 age 加密；家庭注销由运维脚本执行。
14. （2026-10-21 起）伙伴、呀哈哈发现、AI 工作室的全部未指定数值都采用默认值并可由系统管理员修改，逐项列在 [开放问题](open-questions.md) Q5–Q18（标注“已默认，可调整”）。
15. （第 10 部分）AI 角色、技能、执行器的未指定数值（角色预算、步数与超时、页面默认角色、聚合最小分组、导入包限制、只有一位系统管理员时的安全审核）同样采用默认值，见 Q19–Q25；技能里的脚本永不执行；AI 没有任何发布类工具；呀哈哈队长聊天费用计入预算（修订 Q13）。

## 1.3 目标
1. 一个家庭的孩子能在家庭平板/电脑上每天自主完成“闯关 + 复习”，家长能设定时长、看到报告、审批奖励。
2. 学习以**掌握**为中心：间隔复习替代“答对即移除”；星星、碎片、伙伴成长、呀哈哈家族都只奖励掌握与坚持，不奖励被动点击。
3. 正确性可证明：账本（星星与碎片）只追加、余额可对账、所有写操作幂等、并发编辑可检测。
4. 运维足够小：1 台 2 GB 服务器、1 个服务进程、无公网数据库、无常驻语音服务（Piper 只在发布时一次性运行）；素材走 OSS + CDN；AI 费用有月度硬上限；一个人可以维护。
5. 为“开放给更多家庭”预留安全边界：家庭租户隔离、跨家庭功能默认关闭、儿童安全约束内建。
6. 系统管理员能在后台用 AI 工作室制作课程、伙伴与呀哈哈家族款式，并且每一项都经过检查与审核才到孩子面前。
7. 系统管理员能像管理课程一样管理 AI 能力：技能有版本、可回滚、可试运行；AI 角色分工明确、预算可控；多角色流水线一键完成整课；AI 只写草稿，发布永远由人确认。

## 1.4 成功标准（上线验收）
| # | 标准 | 衡量方式 |
| --- | --- | --- |
| S1 | 关键流程可用 | Playwright 端到端用例全部通过：PIN 登录、通关、复习、购买、兑换、赠送、时长锁定、呀哈哈家族、伙伴、工作室、技能与 AI 角色（[§10.4](nfr.md#104-端到端playwrightchromium--webkit)） |
| S2 | 首发内容可学 | 首发英语课程（示例导入 + AI 生成）全部通过自动检查（[§7.4](../03-design/course-model.md#74-自动检查规则k-规则)）并经审核发布，所有题目有图/音素材 |
| S3 | 账本正确 | 并发与重放集成测试通过；上线后每晚对账差异为 0（[§4.5.3](nfr.md)） |
| S4 | 性能 | 生产 ECS 上 10 个并发用户，非 AI 接口 p95 < 300 ms；首屏初始 JS ≤ 200 KB（gzip）；已缓存课程的关卡打开 < 1 s |
| S5 | 可恢复 | 上线前用 OSS 上的备份完成一次恢复演练；RPO ≤ 24 小时，RTO ≤ 2 小时 |
| S6 | 家庭试用 | 上线后 2 周内，家庭的孩子每周至少 5 天使用，且没有“提交丢失/星星不对”的问题报告 |
| S7 | 儿童安全 | 跨家庭自由文本、链接、图片在接口与数据库两层都不可能写入（测试覆盖）；AI 过滤用例集全部通过 |
| S8 | 伙伴正确 | 碎片只来自学习、只用于领养；碎片流水只追加（数据库验证）；经验只来自学习星；营地、门槛、价格复核测试通过 |
| S9 | 呀哈哈家族发现防作弊 | 作答完成前拿不到藏匿点内容；揭晓只成功一次；每日上限在并发下不被突破；规则边界被服务端与数据库拒绝（测试覆盖） |
| S10 | 工作室费用与安全 | 每个任务生成前显示预估费用；当月“预留 + 已花费”从不超过上限（数据库验证）；最多 2 个并发任务；提示词禁止项用例全部通过；未审核内容孩子端不可见 |
| S11 | 技能与 AI 角色可控 | 技能与角色每次修改都产生新版本并可回滚，已保存版本不可改（数据库验证）；面向孩子的技能与角色未经儿童安全审核不能发布；导入的脚本永不执行；工具循环 ≤ 20 步；AI 运行只产生草稿；整课流水线（课程设计师 → 美术设计师 → 配音师 → 质检员 → 系统管理员审核）端到端通过，每步进度与费用可见；全站与角色预算在并发下不超额（[v1.0 验收 S11](../06-releases/v1.0/acceptance.md)） |

## 2. 与旧系统的取舍

依据评审报告 §2–§4。“保留”= 功能意图保留（实现全部重写）；“重设计”= 意图保留但规则/结构改变；“放弃”= 新系统不做。

| 旧功能（评审报告出处） | 取舍 | 新做法 / 理由 |
| --- | --- | --- |
| 登录时选身份，三枚 Cookie，同浏览器多身份（§2.1、F10） | 重设计 | 一枚会话 Cookie，一个浏览器同一时刻一个身份；家长与孩子分属同一家庭；低龄孩子用头像 + PIN |
| 登录限流（IP + 账号，1 分钟 10 次） | 保留（重设计） | 家长：按邮箱 10 次失败锁 15 分钟 + IP 限流；孩子：PIN/密码 5 次错锁 15 分钟（锁状态落库，重启不丢） |
| 空库自动建 `admin/admin` 与演示学生（§2.1） | 放弃 | 安全风险。系统管理员由运维命令创建，强制 TOTP；家庭由注册产生 |
| 管理员（实为家长）与“家长角色”两套账号（F10、I4） | 重设计 | 家长即家庭管理者；系统管理员是独立运维账号，不在任何家庭 |
| 管理员手工创建家长并指派孩子（§2.3） | 重设计 | 家长自助注册（邀请码模式）建家庭，可邀请其他家长，权限相同 |

| 9 种关卡类型 + cloze（§2.2） | 重设计 | 9 种题型：看图选词、听音选词、拼写、跟读、情景对话、排序、填空（选择式）、阅读理解、听辨（2026-10-21 变更，原为 4 种） |
| 一、二年级禁用拼写/阅读 | 保留（重设计） | 变成模板规则与课程自动检查：1–2 年级课程不得含拼写题 |
| 答对 600ms 自动下一题、答错停留看解释 | 保留 | 客户端交互；每题作答后由服务端返回对错与解析（答案不随题下发） |
| 计分 100%=3、≥80%=2、≥60%=1，补差发星 | 重设计 | ≥80% 才通过；100%=3、≥90%=2、≥80%=1；重玩只在星级提高时补差额 |
