# 呀哈哈发现（discovery）· 需求

> 本文为 2026-10-21 设计变更（用户已批准，见 [v1.0 变更记录](../../06-releases/v1.0/changes.md)）新增，对应设计规格 §4.7。旧系统事实参考 `/workspace/greenfield-review/02-宠物-呀哈哈-课程参考.md`。

职责：通关后的藏匿点（服务端决定内容）、点开校验与揭晓、图鉴（album）、呀哈哈家族款式与套组、全局投放设置、投放规则（表单或 AI 填写）与审计、统计。款式形象由 studio 生成，结果归 discovery 所有。

## 4.7.0 命名
- **呀哈哈队长**：AI 聊天助手（原创小树灵，固定形象），见 [chat 需求](chat.md)。
- **呀哈哈家族**：可收集的小精灵款式，藏在关卡地图场景里，被找到后进入图鉴。

## 4.7.1 藏匿点
- **只有通关会打开藏匿点**：每次 `passed=1` 的闯关结算时，在该关的地图场景中打开 3 个藏匿点（树叶、石头、云朵等，来自关卡场景定义）。复习、登录、点喇叭、看卡片等都不打开藏匿点。
- 藏匿点内容**在结算时由服务端决定并记录**（`hiding_spots`），客户端只拿到“藏匿点编号与位置”，不知道里面有没有呀哈哈家族成员。
- 孩子点开：`POST /discovery/spots/:id/reveal`。服务端校验藏匿点属于该孩子、尚未揭晓，然后揭晓：空的返回“这里没有”；有呀哈哈家族成员的播放发现动画与叫声，款式进入图鉴，+1 碎片。重复点开返回第一次的结果，不重复发放。
- 藏匿点不过期：没点开的留到之后点开（例如断网后回来）。

## 4.7.2 概率与每日上限
- 每个藏匿点放置呀哈哈家族成员的概率：全局默认 **20%**（`discovery.spot_probability_pct`，1–100）。
- 每个孩子每个本地日最多放置 **3** 个（`discovery.daily_cap`，1–10）；按“放入藏匿点”计数，点没点开都算。数据库用“当天序号唯一且 ≤ 10”保证并发时也不会超额。
- 界面在关卡路线图显示“今天还能找 N 个”（N = 当日上限 − 今天已放置数，不小于 0）。
- 两项都是 `已默认，可调整`（[开放问题](../open-questions.md) Q11），系统管理员可改。

## 4.7.3 款式、稀有度与图鉴
- 每个款式属于一个**套组**，有稀有度：普通、少见、稀有、传说。稀有度决定抽取权重，默认 100 / 30 / 10 / 2（`discovery.rarity_weights`，Q11）。
- 每个款式可设：每个孩子最多拥有几个（可空 = 不限）、全站总量（可空 = 不限）、上架/下架。达到个人上限或全站总量的款式不会再被抽到。
- **图鉴**：按套组展示已找到/未找到的款式（未找到显示剪影）、每款找到次数、累计找到总数。
- **发现奖励**（`discovery_bonus`，属于奖励星，`已默认，可调整`，Q12）：集齐一套 +5 星（每个套组单独设置，1–50）；累计找到 10 / 30 / 100 个分别 +3 / +5 / +10 星。发现奖励可以花，但**不算学习星**：不计入排行、不给伙伴经验、不计入领养门槛。

## 4.7.4 管理后台
> 第 10 部分：款式设计由美术设计师（`yahaha-style-design`）→ 配音师（`yahaha-voice`）→ 质检员执行；见 [§4.10](agents.md)。

- 全局：开关（`discovery.enabled`；关闭后不再放置，已放置的仍可点开）、概率、每日上限。
- 每个款式：稀有度、个人上限、全站总量、上架/下架。
- 限时活动：用投放规则实现（§4.7.6）。
- 统计：每天放置数、找到数、各款式找到数与剩余库存、各规则的实际消耗、触及每日上限的孩子比例。
- 款式设计：与伙伴相同的 AI 流程（描述 + 风格模板 → 4 张候选 → 选定 → 关键帧 → 动效模板），动效为**弹出、旋转、挥手**，再生成一段叫声；预览 → 草稿 → 审核 → 发布（见 [studio 需求](studio.md)）。

## 4.7.5 投放规则：固定结构
AI 和表单填写的是**同一个固定结构**（字段与校验见 [discovery 设计](../../03-design/modules/discovery.md)）：

| 字段 | 含义 |
| --- | --- |
| 类型 | 限时活动规则 / 课程设定规则 |
| 时间 | 开始时间；结束时间（限时活动必填） |
| 年级 | 适用年级（可空 = 全部） |
| 范围 | 课程设定规则必填 1–20 个目标，每个目标可以是**一门课程、一个单元或一个关卡**（关卡必须同时指明所在单元）；限时活动可选 |
| 触发条件 | 通关 / 单元首次全 3 星级通关 / 指定关卡通关 / 连续学习 N 天 |
| 概率 | 每个藏匿点 1–100% |
| 款式 | 限定可出现的款式（可空 = 全部已上架） |
| 每日上限 | 每孩子每天 1–10 |
| 总量 | 本规则最多放置多少个（可空 = 不限） |
| 对象 | 全部孩子 / 指定年级 |

- **限时活动规则**：时间窗 + 可选的课程/单元/关卡范围；效果为提高概率或限定款式。触发条件固定为“通关”。
- **课程设定规则**：绑定课程、单元或关卡；触发条件为单元首次全 3 星级通关、指定关卡通关、通关或连续学习 N 天；效果为**必得**（在每日上限允许时至少放置一个）或提高概率。

## 4.7.6 规则的创建与生效
> 第 10 部分：“一句话填写规则”由 AI 角色**活动策划**（技能 `drop-rule-fill`）执行，只产出 RuleSpec 草稿；复述、校验与生效规则不变。见 [§4.10](agents.md)。

- **单元首次全 3 星级通关**：指孩子第一次让某个单元（如一年级上册 Unit 3）当前版本中的**全部关卡**都达到 3 星级；每个孩子每个单元只触发一次（由单元进度记录保证），之后课程改版不会再次触发。这一触发的目标只能是课程（其中任何单元）或单元，不能是关卡。
- **指定关卡通关**：每个目标都必须是关卡（课程 + 单元 + 关卡）。

1. 系统管理员用表单编辑，或输入一句自然语言（例如“国庆 7 天，一年级上册 Unit 3 通关概率翻倍，只出森林套组”）让 AI 填写表单。
2. 系统用固定模板把规则**复述成一段大白话**（不是 AI 生成），并估算影响：每个孩子每天预计多找到几个、规则期间预计消耗多少总量。
3. 系统管理员确认 → 保存草稿 → 发布。到开始时间自动生效，到结束时间自动结束；可随时暂停、恢复。
- **安全**：AI 只负责填表，不能直接生效；服务端校验全部边界（概率 1–100%、每日上限 ≤ 10、总量 ≥ 1、结束晚于开始、限时活动必须有结束时间、课程规则必须至少一个目标、目标结构合法且课程/单元/关卡存在、触发条件与目标层级一致），数据库 CHECK 再兜底一次（目标存在性只由服务端校验）。
- **重叠**：发布前列出与之时间和范围重叠的规则并提示；同时生效时，**概率取最高**、**每日上限取最严（最小）**、限定款式取交集（交集为空则取概率最高那条的款式）。
- **审计**：创建、AI 填写（含原始一句话）、修改、发布、暂停、恢复、结束全部写入审计事件。
- 这一“AI 填写固定结构 + 服务端校验 + 大白话复述”的模式以后可复用到伙伴档位设置。

## 4.7.7 与旧系统相比放弃的
| 旧系统 | 新系统 |
| --- | --- |
| 四种来源：单元满星必得、活动随机、单词必得（每学会 5 词）、单词随机 | 只有通关打开藏匿点；“必得”由课程设定规则表达 |
| 四层上限：全局随机日上限、活动日上限、每轮上限、活动配额（另有收藏总上限 1–100000） | 一个全局每日上限 + 规则上限（同时生效取最严）+ 可选的款式个人上限与全站总量 |
| 把“听一次、看一张卡”当作抽签机会 | 不做：被动行为不打开藏匿点；听发音只发积分（ADR 0017），与呀哈哈家族无关 |
| 表结构靠 `_v2`/`_v3` 后缀升级，新旧表并存 | 不做：版本化迁移文件 |
| 每次发奖用 `UPDATE yahaha_settings SET version=version` 拿全局锁 | 不做：每孩子当天序号唯一键 + 该孩子余额行锁 |
| 发现只是结算后的抽签弹窗，地图上没有可找的东西 | 结算时决定并记录 3 个藏匿点，孩子在地图场景里点开 |

## 验收要点
- 同一藏匿点连续点开两次：第一次发放，第二次返回相同结果且不再发放（数据库：揭晓更新影响行数 1 → 0；图鉴与碎片唯一键）。
- 并发 10 次通关：当天放置数不超过上限（数据库验证 `daily_seq`）。
- 规则概率 0 或 101、每日上限 11：服务端 400，数据库 CHECK 拒绝。
- 客户端在作答完成前拿不到藏匿点内容；伪造藏匿点 ID 返回 404。
