职责：只追加账本（星星、碎片与积分）与余额缓存、发放与扣除、星星小铺（探险徽章购买与佩戴、现实奖励兑换与审批、累计奖励与核销）、星级荣誉。

## 4.1.8 星星来源（仅此 11 种）
| 来源 | 流水 kind | 数量 | 算“学习星”（排行、伙伴经验、领养门槛） |
| --- | --- | --- | --- |
| 首次通过或星级提高 | `level_pass` | 1–3（差额） | 是 |
| 连续天数里程碑 | `streak` | 3 / 7 / 20 | 是 |
| 隐藏奖励（ADR 0020） | `hidden_reward` | 翻倍 1–3 或宝箱 20 | 是 |
| 秘密路线通过奖励（ADR 0020） | `secret_reward` | 4 / 10 / 20（入场费 2 倍，每条路线一次） | 是 |
| 单词闯关进步奖励（ADR 0019） | `word_challenge` | 1–30 / 轮（每 5 个新增进度单位 1 颗） | 是（用户 2026-10-22 决定） |
| 单词考试进步奖励（ADR 0019） | `word_exam` | 1–20 / 轮 | 是（用户 2026-10-22 决定） |
| 家长加星（旧系统，带原因） | `parent_award` | 1–1000000 / 次 | 否 |
| 收到赠送 | `gift_in` | 1–20 | 否 |
| 积分换星（10 积分 = 1 颗） | `point_convert` | 1–1000 / 次 | 否 |
| 伙伴退订返还（实付一半，ADR 0020） | `pet_refund` | 1–10000 | 否 |
| 兑换被拒绝或撤回 | `redeem_release` | = 冻结额 | 否 |

前六种来源统称**学习星**；其余统称**奖励星**：可以花，但不计入排行、伙伴经验和领养门槛（见 [GLOSSARY.md](../../../GLOSSARY.md)）。~~呀哈哈发现奖励星 `discovery_bonus`~~ 已删除（旧系统呀哈哈不发奖励，Q12 已决定照旧）。

复习不发星星（旧系统规则；复习答对发积分，完成当日复习发碎片）。看卡片、登录、聊天等被动行为不产生任何流水；点喇叭听发音只发积分（见 §4.1.9），不发星星。看学习卡只发碎片（§4.1.3a）。星星支出：`purchase`（探险徽章）、`pet_adopt`（用星星领养伙伴）、`den_expand`（扩建营地）、`secret_entry`（秘密路线入场费 2 / 5 / 10）、`parent_deduct`（家长扣星）、`gift_out`、`redeem_hold`（冻结）、`redeem_debit`（批准扣除）。

**家长加星与扣星**（旧系统，ADR 0020）：家长在家长中心给本家庭孩子加星（1–1000000）或扣星，**扣星必须写原因**（≤ 300 字），加星可选写原因；扣星不能扣到负数，也不能扣冻结部分（`409 INSUFFICIENT_STARS`）；两者都写审计并给孩子发一条信箱通知。系统管理员不能改任何孩子的星星。

碎片来源与用途见 [companion 需求 §4.6.2](companion.md#462-碎片第二种货币)：只来自 `learning_card`（学习卡首次展示）、`review_day`、`discovery` 与 `pet_refund`，只用于 `pet_adopt`。

**星级荣誉**（旧系统，只展示）：按历史累计学习星 t 计算，太阳 = ⌊t / 1000⌋、月亮 = ⌊(t mod 1000) / 100⌋，显示在“我的设置”与星星伙伴页；不是货币，不能花、不能送。

## 4.1.9 积分（与旧系统完全一致）
积分以 0.01 为单位记账（界面显示两位小数），不设余额上限以外的任何新上限。

| 来源 | 流水 kind | 数量 | 次数与上限 |
| --- | --- | --- | --- |
| 关内听发音：点题目、选项、对话、短文、跟读标准音的喇叭 | `level_listen` | +0.1 | 同一次作答中每个发音目标一次；无每日上限、无冷却 |
| 单词本听发音：单词、英文释义、每条短语、每条例句 | `word_listen` | +0.1 | 每个发音每个本地日一次；每天最多 10 积分；两次得分至少间隔 5 秒 |
| 复习答对 | `review_correct` | +1 / 题 | 每个复习条目每个本地日一次；每天最多 30 积分 |
| 伙伴附赠 | `pet_bonus` | 本次通关新得星数 × 每星比例 | 每次闯关结算或单词闯关结算一次（ADR 0019）；按开始作答时跟随伙伴的等级：1 级每星 0.10 积分，线性升到 100 级每星 1.00 积分（节点与公式见 ADR 0017）；默认最高 100 级 = 每星 1.00 |

- 用途只有**换星**：`POST /points/conversions {stars}`，10 积分 = 1 颗星星，一次 1–1000 颗，积分不足 → `409 INSUFFICIENT_POINTS`；换来的星星是奖励星。积分不能直接购买装扮、兑换现实奖励、赠送，家长不能发放。
- 关内听发音：目标必须属于这次作答的可见部分并带音频；作答已结束 → `409 PLAY_FINISHED`；已得过 → 200 `{awarded: false}`（“本轮已获得过发音积分啦”）；孩子端关闭声音时不上报。
- 单词本：v1.0 **包含**单词本（用户 2026-10-22 决定，[ADR 0019](../../adr/0019-wordbook-as-old-system.md)），`word_listen` 照上表生效：`POST /wordbook/listen`，发音键是归一化后的发音文本；考试中不发；关声音时不上报。
- 孩子端“积分”页：余额、今日复习积分（x / 30）、今日单词本听读积分（x / 10）、最近流水、换星按钮。家长中心流水页同样显示积分流水。

## 4.2.1 账本与余额
- `ledger` 只追加：每行 `currency`（`star` / `fragment` / `point`；积分以 0.01 为单位）、`kind`、`delta`（正负号由 kind 决定，CHECK 约束）、`balance_after ≥ 0`（该币种余额）、`source_key`（同一孩子同一币种唯一，业务级幂等）、`local_date`。数据库 CHECK 规定每个币种允许哪些 kind、每个 kind 的数量范围。
- **可用余额 = 该孩子该币种全部流水 `SUM(delta)`**。`balances`（主键 `(child_id, currency)`）是同一事务内维护的缓存，同时充当行锁；每晚对账（[§3.6](../../02-solution/overview.md#36-后台任务进程内调度器单实例)）。没有任何“直接改余额”的接口或 SQL。
- 一个操作同时涉及多个币种时（例如通关同时发星星、碎片与伙伴附赠积分，换星同时扣积分加星星），按固定顺序 `star` → `fragment` → `point` 加锁（[§4.5.2](../nfr.md)）。
- “冻结中”= 该孩子待审批兑换的价格之和（`redemptions.status='pending'`）。孩子界面显示“可用 N 颗，冻结 M 颗”，以及碎片与积分余额。

## 4.2.2 探险徽章
- 探险徽章（旧系统“装饰徽章”，原规格的三槽装扮取消）由系统管理员在后台维护：ID、名称、价格（1–1000）、图片（素材库）、上架/下架；初始数据来自仓库 `seeds/shop/`。图片必须原创或已授权（提示词禁止词表同样适用于上传的名称与描述）。
- 购买 `POST /shop/purchases {itemId, expectedPrice}`：服务端读取**当前**价格；与 `expectedPrice` 不同 → `409 PRICE_CHANGED`（返回新价格，孩子确认后重试）；已下架 → `404`；已拥有 → `409 ALREADY_OWNED`；余额不足 → `409 INSUFFICIENT_STARS`。成功则同一事务写 `purchase` 流水（`source_key = purchase:{itemId}`）与 `child_items`。
- 每件物品每个孩子只能买一次；无退货、无转赠。下架物品不再出售，已拥有的仍可穿戴。
- 佩戴：`PUT /me/badge {itemId | null}`；同时只佩戴一枚（唯一键），显示在头像角上。伙伴不在小铺里，见 [companion 需求](companion.md)。

## 4.2.2a 星星小铺四卡（旧系统）
孩子端“星星小铺”页照旧系统 2026-10-21 用户确认的四卡结构：
| 卡片 | 内容 |
| --- | --- |
| 喜欢的时光 | 本家庭的现实奖励目录，按份兑换（§4.2.3） |
| 探险徽章 | 徽章列表、购买与佩戴（§4.2.2） |
| 累计奖励 | 已获批的奖励余额（如“玩游戏机 剩余 30 分钟”），孩子点“用掉”记一次使用（§4.2.3） |
| 复习积分 | 积分余额、今日复习积分（x / 30）、换星按钮，以及进入复习的入口（§4.1.9） |

## 4.2.3 现实奖励兑换与累计奖励（旧系统，ADR 0020）
- 家长维护本家庭的奖励目录（乐观锁）：标题 ≤ 40 字、说明、**单位**（分钟 / 金额（分）/ 次数）、**每份数量**（1–100000）、**每份星价**（1–2000）、启用 / 停用。新家庭创建时写入旧系统的 3 项默认，家长可改可停用：玩游戏机 10 分钟 / 20 星、玩具额度 ¥1 / 1 星、选择家庭游戏 1 次 / 5 星。
- 孩子按**份**申请（1–1000 份）→ 冻结 `份数 × 每份星价`；家长批准 → 扣除，并把 `份数 × 每份数量` 加进该奖励的**累计奖励余额**；拒绝 → 释放；孩子可撤回待审批申请 → 释放。每个孩子最多 3 个待审批申请。
- 申请时做价格复核（`expectedPrice` = 每份星价）；申请单保存标题、单位、份数与每份星价快照，之后家长改价不影响已申请的单。
- **累计奖励**：每个孩子每项奖励一个余额（`reward_balances`），流水只追加（`reward_ledger`：获批入账 / 孩子用掉 / 家长核销）。
  - 孩子“用掉”：`POST /child/rewards/:optionId/uses {amount, note?}`，记一次使用，不需要审批（旧系统）；
  - 家长“核销”：`POST /children/:id/rewards/:optionId/writeoffs {amount, reason}`，必须写说明（≤ 300 字），用于“已经兑现了”的记录；
  - 余额不能为负（`409 REWARD_BALANCE_INSUFFICIENT`）；入账、用掉、核销都给对方发信箱通知。
- 只能用星星兑换，碎片和积分不能兑换。

## 验收要点
- 星星只有表中 11 种来源、碎片只有 4 种来源、积分只有 §4.1.9 的 4 种来源；登录、聊天不产生任何流水，看学习卡只产生 `learning_card` 碎片流水，点喇叭只产生 `level_listen` 积分流水（集成测试遍历这些接口后核对账本行数）；复习结算不写任何星星流水。
- 积分：同一次作答同一发音目标只得一次 0.1；复习答对每个条目每天一次、每天最多 30 积分（第 31 题起不再发）；伙伴附赠 = 星数 × 比例（1 级 0.10、30 级 0.27、100 级 1.00）；换星 10 : 1、1–1000 颗、不足返回 `INSUFFICIENT_POINTS`，换来的星星不计学习星；同一请求 ID 重放只换一次。
- 账本只追加：应用数据库账号对 `ledger` 的 UPDATE/DELETE 被拒（[附录 A](../../03-design/data-model.md#附录-a-数据库验证结果)）；任一孩子任一币种 `SUM(delta)` = `balances.balance` = 最后一行 `balance_after`，夜间对账差异为 0。
- 同一 `source_key` 并发或重放只入账一次；余额不足时购买、领养、赠送、兑换均被拒且不写任何流水。
- 购买时价格已变 → `409 PRICE_CHANGED`，孩子确认新价格后重试成功；同一徽章只能买一次；同时只能佩戴一枚。
- 家长扣星不写原因 → 400；扣到冻结部分 → `409 INSUFFICIENT_STARS`；单词星、隐藏奖励、秘密路线奖励计入学习星，家长加星与秘密路线入场费不计。
- 兑换 3 份“玩游戏机”（每份 10 分钟 / 20 星）：冻结 60 星；批准后累计余额 30 分钟；孩子用掉 10、家长核销 10 后余额 10；再用掉 20 → `409 REWARD_BALANCE_INSUFFICIENT`。
- 星级荣誉：历史学习星 1234 → 1 个太阳、2 个月亮。
- 兑换：申请冻结、批准扣除、拒绝或撤回释放，三者之后“可用 + 冻结”与流水一致；每个孩子最多 3 个待审批申请；碎片不能用于兑换。
- 通关同时发星星、碎片与积分时按“星星行 → 碎片行 → 积分行”加锁，并发测试无死锁。
