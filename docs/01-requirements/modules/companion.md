## 4.6.1 档位与领养
- 每个伙伴种类属于一个**档位**。档位定义：星星价、碎片价、是否全站唯一、等级曲线、成长阶段。种类可以**单独定价**（为空则跟随档位），并分别开关“可用星星领养 / 可用碎片领养 / 可赠送”（旧系统）。系统管理员可在后台修改（乐观锁，审计）。
- 默认档位（**已决定（用户 2026-10-22）**：照旧系统，[开放问题](../open-questions.md) Q5）：

| 档位 | 星星价 | 碎片价 | 说明 |
| --- | --- | --- | --- |
| 初级 | 20 | 80 | |
| 中级 | 50 | 160 | |
| 高级 | 100 | 320 | |
| 稀有 | 250 | 800 | |
| 唯一 | 600 | 2000 | 每个种类**全站同时只能有一个孩子拥有**（旧系统“全岛唯一”；数据库唯一键）；已被领养时显示“已有主人” |

- **领养门槛**：全站一个门槛（系统设置 `companion.unlock_stars`，默认 0，旧系统），口径 = 历史累计“学习星”。
- “学习星”= 星星流水中 `level_pass`、`streak`、`hidden_reward`、`secret_reward`、`word_challenge`、`word_exam` 之和（与周排行口径相同；复习不发星星，ADR 0017；单词星算学习星，用户 2026-10-22）；家长加星、收到赠送、积分换来的星星、退订返还等**奖励星**都不算。
- **种类来源**：旧系统 24 种宠物（`origin = seed`，[ADR 0021](../../adr/0021-nintendo-pets-seed.md)）由 `xingya seeds:apply` 从 `seeds/pets/` 导入并直接上架；AI 工作室设计的原创伙伴（`origin = studio`）经审核后上架（§4.6.6）。两者在领养列表中并列，按档位排序。
- 领养：`POST /companion/adoptions {speciesId, payWith: 'star'|'fragment', expectedPrice}`。孩子可**任选星星或碎片**支付；服务端检查：种类已上架、未拥有该种类（每种每人 1 只）、达到门槛、营地有空格、价格与 `expectedPrice` 一致（否则 `409 PRICE_CHANGED`）、余额足够。同一事务写 `pet_adopt` 流水与 `child_pets`。
- 孩子的第一只伙伴自动成为跟随伙伴。
- 伙伴不做物理删除；下架的种类不再可领养，已领养的保留。
- **退订**（旧系统）：`POST /companion/pets/:id/refund`，按原支付币种退还**实付的一半**（向下取整，`pet_refund`），伙伴状态改为“已退订”，营地空出一格，之后可以再领养同一种；跟随伙伴不能退订（先换跟随伙伴）。⚠ **受赠的伙伴不能退订**（数据库 CHECK）——否则“送宠物 → 对方退订”可以绕过每天赠星 ≤ 20 的用户规则（ADR 0020 R4）。
- **赠送**（旧系统）：`POST /companion/pets/:id/gifts {toChildId}`，把伙伴连同等级、经验、亲密度、名字转给另一个孩子；种类须允许赠送；对方营地须有空格、没有同种伙伴；唯一档照样全站一只。同家庭直接送；跨家庭条件与赠星相同（好友家庭、双方开启跨家庭、未屏蔽，[social 需求](social.md)）。双方各收到一条信箱通知。

## 4.6.2 碎片（第二种货币）
- 碎片与星星记在**同一本只追加账本**（`ledger.currency='fragment'`），同样有余额缓存、幂等键、每晚对账，应用账号不能修改或删除流水。
- 碎片**只能通过学习获得**：

| 来源 | 流水 kind | 数量 |
| --- | --- | --- |
| 学习卡第一次展示（每次作答每张卡一次） | `learning_card` | 1–3（服务端加密随机；旧系统，Q7 已决定照旧） |
| 完成当日复习 | `review_day` | 2（用户指定） |
| 每找到 1 个呀哈哈家族成员 | `discovery` | 1（用户指定） |
| 退订用碎片领养的伙伴 | `pet_refund` | 实付的一半 |

- 通关**不发**碎片（旧系统没有通关碎片）。
- 碎片只用于领养伙伴（`pet_adopt`）；营地扩建只能用星星；不能购买装扮、不能兑换现实奖励、不能赠送、家长不能手动发放（数据库 CHECK 保证币种与类型匹配）。

## 4.6.3 营地（den）
- 每个孩子的营地默认 3 格（系统设置 `companion.den_base_slots`，1–10）；已领养伙伴数 ≤ 营地格数。
- 扩建：`POST /companion/den/expansions {expectedPrice}`，**只能用星星**支付，价格依次取 `companion.den_slot_prices`（默认 `[10, 20, 100, 200, 500]`，即最多扩建 5 次；**已决定（用户 2026-10-22）**：照旧系统，Q10）。扩建格数上限 10（CHECK）。扩建成功发一条信箱通知。

## 4.6.4 成长：经验、等级、阶段
- 只有**跟随伙伴**获得经验：孩子每获得 1 颗学习星（含单词星、隐藏奖励、秘密路线奖励），跟随伙伴 +1 经验，在发星的同一事务内写入。**不消耗星星**，没有喂食、饥饿。
- ⚠ 旧系统升级是**花星星**逐级升级（满级共 2191 星）；用户 2026-10-22 在单词星决定中写明单词星“计入伙伴经验”，因此保留“学习星加经验”，曲线照旧（见 ADR 0020 §8 第 4 点）。
- **伙伴附赠积分**（旧系统规则，ADR 0017）：闯关结算时，若本次 `level_pass` 新得星数 > 0，且开始作答时有跟随伙伴，另发 `星数 × 每星比例` 积分（`pet_bonus`）；星数 = 本次 `level_pass` 差额 + 隐藏奖励（旧系统“含隐藏奖励”）；秘密路线通过时按 `secret_reward` 附赠；比例按开始作答时跟随伙伴的等级（`plays.companion_level` 快照），1 级每星 0.10 积分，线性升到 100 级每星 1.00 积分。默认最高 100 级（与旧系统一致），满级为每星 1.00 积分。复习不附赠。**单词闯关**同样附赠（与旧系统一致，[ADR 0019](../../adr/0019-wordbook-as-old-system.md)）：本轮单词星 × 每星比例，等级取开始这一轮时的快照（`word_tasks.companion_level`），`source_key = petbonus:word:{taskId}`；单词考试与单词学习不附赠。单词星算学习星，给伙伴加经验（用户 2026-10-22 决定）。
- 等级曲线按档位配置：从 L 级升到 L+1 级需要 `xp_base + xp_step × ⌊(L − 1) / 10⌋ + ⌊(L − 1)² / xp_quad_div⌋` 经验；默认 `2 / 1 / 200`，即旧系统 `petUpgradeCost` 曲线 `2 + ⌊(L−1)/10⌋ + ⌊(L−1)²/200⌋`（1→2 级 2、10→11 级 2、20→21 级 4、50→51 级 18、99→100 级 59；累计到 20 级 51、到 50 级 364、到 100 级 2191 经验），最高 **100 级**（用户 2026-10-22 决定，与旧系统一致；Q8）。曲线数值照旧（**已决定（用户 2026-10-22）**）。
- 成长阶段按档位配置（最多 4 个），默认：

| 阶段 | 起始等级 | 新解锁动作 |
| --- | --- | --- |
| 幼苗 | 1 | 呼吸待机（idle-breathe）、开心跳（happy-bounce） |
| 探险 | 20 | 欢呼跳（cheer-jump） |
| 守护 | 50 | 开心挥手（happy-wave） |
| 星耀 | 100 | 欢呼转圈（cheer-spin） |

阶段起始等级 1 / 20 / 50 / 100 与旧系统 `petStage` 一致（2026-10-22 随最高等级改为 100，原为 1 / 5 / 12 / 20）。

- 进入新阶段：切换为该阶段的形象图，解锁新动作，播放一次升级台词。
- **成长装扮**（旧系统）：20 级起戴围巾、50 级起戴徽章、100 级有光环，由客户端叠加在形象上（种子宠物只有一张基础图，阶段变化全靠叠加层）。
- 切换跟随伙伴：`PUT /companion/active {childPetId}`，不影响各伙伴已有等级。

## 4.6.5 互动
- 点击伙伴播放动画与声音（待机、开心、欢呼，以及已解锁的动作；问候、鼓励、升级台词）。
- **摸摸 / 点心 / 玩耍**（旧系统）：`POST /companion/pets/:id/interactions {action: pet|feed|play}`，每只伙伴每种动作每个本地日一次，亲密度 +1（上限 100）；亲密度**只展示**，不发任何奖励、不影响经验。
- **改名**（旧系统）：`PUT /companion/pets/:id {nickname}`，1–12 字，保存前过滤个人信息（`400 TEXT_BLOCKED`）；为空则显示种类名。
- 学习中：答对后跟随伙伴播放“开心”，通关播放“欢呼”与鼓励台词。
- 动画 = 关键帧图片 + 预设动效模板，由客户端渲染（[ADR 0013](../../adr/0013-keyframe-motion-template-animation.md)）；“减少动画”设置下只显示静态形象。

## 4.6.6 伙伴设计（后台，AI 工作室）
> 第 10 部分：以下 AI 步骤由 AI 角色执行——美术设计师（技能 `pet-design`：候选、阶段图与动作关键帧）→ 配音师（`pet-voice`：台词与变调）→ 质检员（`content-qa`）；可在伙伴页一句话框或“伙伴流水线”一键运行。AI 只写种类草稿，审核与上架仍由系统管理员操作。见 [§4.10](agents.md)。

1. 系统管理员输入描述 + 选择风格模板 → 生成 4 张候选形象。
2. 选定一张作为基础形象。
3. 基于基础形象生成各成长阶段的形象图，以及动作关键帧（待机 idle、开心 happy、欢呼 cheer）。
4. 为动作套用预设动效模板（呼吸、弹跳、跳跃、挥手、转圈）。
5. 选择声音与音高，生成台词音频（问候、鼓励、升级）：Piper 合成 + ffmpeg 变调，生成时一次完成（Q17）。
6. 预览 → 保存草稿 → 提交审核 → 发布 → 设置档位（价格随档位，或单独定价）。
- 生成前显示预估费用，受月度 AI 预算上限约束（见 [studio 需求](studio.md)）。
- 提示词自动追加禁止项：不得模仿现有动漫/游戏角色（**任天堂角色同样禁止**，即使种子集里有；ADR 0021），不得指名在世艺术家的风格；命中提示词禁止词表的描述直接拒绝。美术设计师不能编辑 `origin = seed` 的种类形象。
- 选择“关键帧 + 动效模板”而不是 AI 视频：成本低、风格稳定、文件小、可离线缓存、动作可控且适合儿童。

## 4.6.7 与旧系统的对照（2026-10-22 起照旧，ADR 0020）
| 旧系统 | 新系统 |
| --- | --- |
| 退订返还一半 | **照旧**；受赠的伙伴不能退订（⚠ 防绕过赠星上限） |
| 赠送宠物 | **照旧**；跨家庭条件与赠星相同（⚠ 安全规则） |
| 全站唯一宠物 | **照旧**：唯一档 |
| 物理删除宠物 | 不做：退订、赠出只改状态；下架只停止领养 |

## 验收要点
- 碎片不能用于领养以外的任何支出；碎片流水应用账号无法 UPDATE/DELETE（数据库验证）。
- 同种伙伴同时不能有两只；营地满时领养返回 `409 DEN_FULL`；未达门槛返回 `409 THRESHOLD_NOT_MET`；唯一档已被别人领养返回 `409 PET_UNIQUE_TAKEN`。
- 用 50 星领养的伙伴退订得 25 星，营地空出一格，可再领养同种；受赠的伙伴退订返回 `409 PET_NOT_REFUNDABLE`。
- 赠送后伙伴出现在对方营地，等级与亲密度不变；对方营地满 → `409 DEN_FULL`；跨家庭未成为好友 → `403 NOT_FRIENDS`。
- 同一只伙伴当天第二次“摸摸”不再加亲密度；亲密度到 100 后不再增加。
- 首次部署后领养列表有 24 种种子宠物，价格与档位照旧系统（如马里奥 50 星 / 100 碎片、罗莎塔 600 / 2000 唯一）。
- 发 3 颗学习星 → 跟随伙伴经验 +3；家长奖励 10 星（奖励星）→ 经验不变。
- 越过阶段起始等级时形象切换、新动作出现。
