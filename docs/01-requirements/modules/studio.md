# AI 工作室（studio）与 AI 生成课程 · 需求

> 本文为 2026-10-21 设计变更（用户已批准，见 [v1.0 变更记录](../../06-releases/v1.0/changes.md)）新增，对应设计规格 §4.8（AI 生成课程）与 §4.9（AI 工作室）；第 10 部分“Skill 管理与 AI 角色”（§4.10）也属于本模块，见 [Skill 管理与 AI 角色 · 需求](agents.md)。只有系统管理员可用（呀哈哈队长除外，它是面向孩子的 AI 角色）。

## 边界：content 与 studio 怎么分
| 归属 | 内容 |
| --- | --- |
| **studio**（能力层） | 任务队列（`ai_jobs`）、提供方适配器（图像、语音 TTS、LLM、OCR）、素材库（`assets`）、资料库（`materials`）、月度预算（`ai_budget_months`）、费用预估、提示词禁止词表；**技能库、AI 角色、角色执行器、流水线、任务历史、快捷任务、角色预算**（§4.10） |
| **content**（课程的所有者） | 词库、课程、草稿、模板、自动检查、表单编辑、审核、发布、版本 |
| **companion / discovery** | 伙伴种类、呀哈哈家族款式与投放规则的数据与生命周期 |

- 规则：**studio 只负责“生成东西”，不拥有任何业务对象**。AI 流程由 **AI 角色 + 技能**执行（§4.10）；各业务模块向 studio 注册**内置工具**（如 `course.write_draft`、`pet.write_design`、`rule.write_draft`，只读或只写草稿，没有发布类工具），工具在业务模块自己的事务里写自己的表。确定性的系统任务（发布时生成音频、资料文本抽取）仍以任务处理器注册。studio 只依赖 platform，不依赖任何业务模块。

## 4.8 AI 生成课程

> 2026-10-21 用户决定（[ADR 0016](../../adr/0016-unit-layer.md)）：课程 = 一册，由若干单元组成；一次生成可以产出**一个单元**（加入已有课程的草稿）或**整门课程**；模板规定每个单元的关卡结构；费用按单元预估。

### 4.8.1 流程
1. **上传资料**：PDF、Word（docx）、PPT（pptx）、照片、纯文本，单个 ≤ 20 MB。文本类直接抽取文字；照片用 OCR 识别。扫描版 PDF（无文字层）首发不支持，提示改为上传照片（`已默认，可调整`，[开放问题](../open-questions.md) Q14）。
2. **AI 分析**（课程设计师 · 资料分析技能）：从资料中整理出**单词、句型、知识点**清单；系统管理员可增删改。单词与词库比对：已有义项直接引用，新词/新义项作为候选（`draft`），发布课程时才转为正式。
3. **选择模板与生成范围**（§4.8.3）：生成**整门课程**（AI 先按资料拆分单元，系统管理员确认单元列表：单元数、每个单元的主题与 `unit_key`）或**单个单元**（指定已有课程的草稿和新单元的位置与主题，生成结果作为新单元加入该草稿，其他单元不动）。
4. **生成**（课程设计师 · 按模板生成；也可一键运行“整课流水线”：课程设计师 → 美术设计师配图 → 配音师试听 → 质检员，见 [§4.10.5](agents.md#4105-便捷功能)）：按模板为每个单元生成关卡、题目、答案、解析，并为题目配图，**同一课程使用统一画风**。生成前显示预估费用，**按单元列出**（每个单元的 LLM、配图、OCR 费用小计 + 合计）；超出本月剩余预算时不能开始。整门课程按单元逐个生成，一个单元失败不影响已生成的单元，可只重跑失败的单元。
5. **自动检查**（§4.8.4）：未通过的题目标红并写明原因。
6. **编辑**：表单编辑（不显示原始 JSON）：增删单元、调整单元与关卡顺序；每题可“让 AI 重写这一题”（可附一句要求）；“孩子视角试玩”按孩子看到的样子逐关走一遍（可只试玩一个单元；不记录进度、不发奖励）。
7. **审核与发布**：自动检查全部通过才能提交审核；审核与发布以**整门课程**为单位（只加了一个单元也发布整门课程的新版本）；发布时后台任务生成全部音频（Piper 一次性进程）并把素材复制到公开 CDN 前缀，然后写入新的不可变课程版本。

### 4.8.2 不变的规则
- 题型、判分、通过线与星级规则见 [learning 需求](learning.md)，AI 生成的课程与手工课程完全相同；跟读题仍不计分。
- AI 生成内容在发布前一定经过系统管理员审核；孩子永远看不到未审核内容。

### 4.8.3 课程模板（首发 4 个）
模板定义放在仓库 `seeds/course-templates/`（随发布包部署、api 启动时读取、版本化），规定**每个单元**的关卡结构（关卡顺序、每个单元的关卡数，在系统设置 `content.unit_levels` 默认 3–6 范围内）、题型组合、每关题数、适用年级。一门课程使用一个模板，所有单元结构相同（开放问题 Q27）。

| 模板 | ID | 每个单元的关卡与题型 | 每关题数 | 适用年级 |
| --- | --- | --- | --- | --- |
| 单词闯关课 | `word-quest` | 认识（看图选词、听音选词）→ 练习（+ 跟读）→ 挑战（+ 拼写，仅 3–6 年级）；4 种题型 | 5–8 | 1–6（1–2 年级无拼写） |
| 句型对话课 | `sentence-dialogue` | 情景对话 → 排序 → 填空（+ 跟读） | 5–8 | 1–6 |
| 绘本阅读课 | `picture-book` | 绘本分页（图 + 句 + 音频）→ 阅读理解（+ 跟读） | 5–8 | 1–6 |
| 自然拼读课 | `phonics` | 字母与发音规则 → 听辨 → 听音选词（+ 跟读） | 5–8 | 1–3 |

- 每关至少 4 道计分题。模板 ID 与自然拼读的年级范围为 `已默认，可调整`（Q16）。

### 4.8.4 自动检查
| 检查 | 不通过的例子 |
| --- | --- |
| 结构 | 缺字段、题型与模板不符、每关题数不在 5–8、计分题少于 4、课程没有单元、单元关卡数不在 3–6（`content.unit_levels`）、`unit_key` 在课程内重复或 `level_key` 在单元内重复 |
| 答案在选项中 | 选择题的正确选项 ID 不在选项里；排序题答案不是词块的一个排列 |
| 重复 | 同一关两道题题干与答案相同；同一题选项重复 |
| 年级规则 | 1–2 年级出现拼写题；题型不在模板允许范围 |
| 干扰项过近 | 干扰项与答案只差大小写/空格，或是答案的同义可接受答案 |
| 资源齐全 | 需要图片的题没有图片；义项缺释义 |
| 内容安全 | 题干、选项、解析命中安全词表 |

检查结果保存在草稿上；任何修改都使“已通过”失效，需重新检查（数据库：未通过检查的草稿不能进入审核）。

## 4.9 AI 工作室

### 4.9.1 任务队列
- 所有 AI 与音频生成都是后台任务，记录在 MySQL（`ai_jobs`），由 api 进程内的任务执行器消费。
- **同时最多 2 个任务在运行**（数据库槽位唯一键保证）；其中需要本机进程（Piper、ffmpeg）的同时最多 1 个，以守住 2 GB 内存预算。
- 任务有心跳（15 秒）；超过 2 分钟无心跳视为中断，最多重试 3 次。系统管理员可取消排队中的任务。
- 后台“任务”页显示排队、运行、成功、失败、预估与实际费用。

### 4.9.2 提供方适配器
- 图像生成、语音（TTS）、LLM、OCR 各一个适配器接口；具体厂商在配置中选择（推荐见 Q15）。语音默认用本机 Piper（无费用）。
- LLM 输出必须是结构化 JSON，用 Zod 校验；校验失败的结果不写入草稿，任务标记失败并显示原因。

### 4.9.3 素材库
- 图片（webp ≤ 300 KB）、音频（单声道 MP3 ≤ 200 KB）、动画清单（关键帧 + 动效模板，≤ 64 KB）。按内容哈希命名，存放在阿里云 OSS。
- 草稿素材在 OSS 私有前缀，管理端用 10 分钟有效的签名 URL 查看；发布时复制到公开前缀，经 CDN 提供给孩子端。
- 素材记录来源（AI 图像/TTS/合成/上传）、提供方、模型与最终提示词。

### 4.9.4 费用控制
- 每个任务入队前按单价表（系统设置 `studio.unit_prices`）计算**预估费用（上限）**并显示给系统管理员，确认后才入队；入队时从本月预算中**预留**这笔费用，结束后按实际费用结算（实际不得超过预估）。
- 每月 AI 预算上限默认 **¥200**（`studio.default_monthly_cap_fen`，`已默认，可调整`，Q13）；可在后台修改当月上限。**预留 + 已花费 ≤ 上限** 由数据库保证；超出时任务不能入队。
- 每个 AI 角色另有**月度预算**（在全站上限之内，§4.10.3）；运行时全站与角色预算同时预留，任一不足都不能开始。
- 呀哈哈队长聊天的 LLM 费用**计入**全站上限与其角色预算（第 10 部分修订 Q13）；另有每日条数配额（见 [chat 需求](chat.md)）。预算用完时孩子端显示友好提示（Q25）。

### 4.9.5 提示词安全
- 仓库 `seeds/safety/prompt-blocklist` 维护禁止词表：现有动漫/游戏/影视角色与品牌、在世艺术家姓名、不适合儿童的内容。命中的描述直接拒绝。
- 所有图像提示词自动追加：“原创角色，不得模仿任何现有动漫、游戏或影视角色，不得模仿任何在世艺术家的风格，适合 6–12 岁儿童”。
- 上传资料中的文字只作为“待分析资料”传给 LLM，不作为指令（提示词注入防护，见 [nfr](../nfr.md)）。

### 4.9.6 后台页面（admin/studio）
- **伙伴**（pets）：设计流程见 [companion 需求 §4.6.6](companion.md#466-伙伴设计后台ai-工作室)；档位与阶段设置。
- **呀哈哈家族**（yahaha）：款式设计、套组、全局设置、统计。
- **课程**（courses）：资料、AI 分析、模板、生成（整门课程或单个单元）、单元列表与排序、编辑、检查、试玩、审核、发布、版本历史。
- **规则**（rules）：投放规则表单 / 一句话生成、复述与影响估算、重叠提示、发布与暂停、审计记录。
- **技能库**（skills）、**AI 角色**（agents）、**任务历史**（runs，含流水线进度、克隆重跑、快捷任务）：见 [§4.10](agents.md)。
- 每个页面顶部都有**一句话框**（默认交给该页面的角色，可 `@角色`），见 [§4.10.5](agents.md#4105-便捷功能)。

## 验收要点
- 第 3 个任务在已有 2 个运行时只能排队（数据库验证：第 3 个运行槽位被拒）。
- 本月剩余预算不足时任务不能入队；已入队任务的实际费用不超过预估（数据库 CHECK）。
- 命中禁止词的描述被拒；生成的提示词都含自动追加的禁止项（素材 `prompt` 字段可查）。
- 孩子端请求草稿素材的签名 URL 返回 403。
- 角色与技能相关验收见 [§4.10 验收要点](agents.md#验收要点)。
