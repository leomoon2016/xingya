> 2026-10-21 用户决定（[ADR 0016](../../adr/0016-unit-layer.md)）：课程与关卡之间有**单元**；单元在课程内按顺序解锁，关卡在单元内按顺序解锁。

职责：单元与关卡路线及解锁、单元进度、作答（下发可见题目、逐题判分反馈、完成结算）、最佳星级、义项与错题的间隔复习、连续学习天数。

## 4.1.2 课程开放、单元与关卡解锁
- 课程开放规则（唯一规则，由 controls 判断）：
  `open(child, course) = course.status = 'active' AND course.current_version_id IS NOT NULL AND ( override = 'open' OR (override 不存在 AND course.grade = child.grade) )`，
  其中 `override` 是 `course_overrides` 中该孩子该课程的记录；`closed` 即关闭。
- 开放以**年级 / 课程**为单位（家长不能按单元开放或关闭）；课程开放后，单元与关卡按下面的顺序解锁。
- 孩子看到的是课程的**当前已发布版本**（`courses.current_version_id`）。单元用跨版本稳定的 `unit_key`、关卡用单元内稳定的 `level_key` 标识；关卡进度按 `(孩子, 课程, unit_key, level_key)`、单元进度按 `(孩子, 课程, unit_key)` 记录，课程改版不丢进度。
- **单元解锁**：第一个单元总是解锁；第 N+1 个单元在第 N 个单元**完成**（当前版本中该单元全部关卡都已通过）后解锁——即单元 N 最后一关通过时，单元 N+1 第一关解锁。单元一旦完成就记下首次完成时间（`unit_progress.first_completed_at`），之后新版本给单元 N 增加关卡也不会把单元 N+1 重新锁上（新增的关卡照常可玩）。
- **关卡解锁**（在已解锁的单元内）：单元第一关随单元解锁；之后每一关在“同一单元内前一关（按当前版本顺序）已通过”或“本关已有通过记录”时解锁。新版本中途插入的关卡不会把已通过的后续关卡重新锁上；新版本删掉的关卡或单元不再显示，但历史记录保留。
- 单元进度（每次结算时在同一事务内更新）：关卡数、已通过关卡数、3 星级关卡数、首次完成时间、首次全 3 星级时间；首次全 3 星级通关时把触发条件“单元首次全 3 星级通关”传给呀哈哈发现（每个孩子每个单元只触发一次）。
- 孩子年级改变后，旧年级课程不再默认开放，但已有进度保留；家长可用 `open` 覆盖重新开放。

## 4.1.3 题型（9 种）
| 类型 | 代码 | 呈现 | 作答 | 计分 |
| --- | --- | --- | --- | --- |
| 看图选词 | `pick_image` | 图片 | 从 3–4 个词选项中选一个 | 是 |
| 听音选词 | `listen_choose` | 播放标准音（可重复） | 从 3–4 个词选项中选一个 | 是 |
| 拼写 | `spell` | 图片 + 中文提示 + 可播放发音 | 键入或点选字母拼出单词 | 是：去首尾空格、大小写不敏感、`’`/`'` 视为同一字符，与标准答案或可接受答案之一完全相同 |
| 跟读 | `read_aloud` | 播放标准音（词或短句） | 录音 → 依次回放“标准音 / 我的录音”自我对比 | **否**：无自动评分；不计入正确率；录音只在浏览器内存，离开题目即丢弃，从不上传 |
| 情景对话 | `dialogue_choose` | 情景图 + 1–3 句对话（可播放） | 为空缺的一句从 3–4 个选项中选择 | 是 |
| 排序 | `order` | 3–6 个打乱的词块或句子 | 拖动/点选排成正确顺序 | 是：整个顺序完全正确才算对 |
| 填空 | `cloze` | 一句话，一处空缺 | 从 3–4 个选项中选一个（首发不做自由键入） | 是 |
| 阅读理解 | `reading_choose` | 绘本页（图 + 句 + 音频）后的问题 | 从 3–4 个选项中选一个 | 是 |
| 听辨 | `listen_discriminate` | 播放一个音（字母音或词） | 从 2–4 个发音相近的选项中选出听到的那个 | 是 |

- 麦克风不可用或孩子拒绝授权时，跟读题显示“听一听再大声读”并可直接继续；记录 `{done:false}`，不影响通过。
- **每次下发都重新打乱选项顺序**（排序题打乱词块顺序）；选项在课程里有稳定的选项 ID，但**下发给孩子端的是本次作答专用的随机令牌**（每次作答重新生成，映射只存在服务端 `plays.items`），因此记住“o1 总是对的”或从词块 ID 推出顺序都不可能；可见部分也不下发义项 ID 等可反查答案的字段。判分时服务端把令牌映射回选项 ID，只看所选选项或提交的顺序。
- 1–2 年级课程不得含 `spell`（由模板与自动检查保证，见 [课程模型](../../03-design/course-model.md)）。
- 每关 5–8 题，其中至少 4 道计分题；每个模板规定本模板可用的题型组合（见 [studio 需求 §4.8.3](studio.md#483-课程模板首发-4-个)）。

## 4.1.4 判分、通过与星级
- 计分题数 `S`（4–8）、答对数 `C`；正确率 `accuracy = floor(C×100/S)`。跟读题不进入 `S`。
- 通过：`C×100 ≥ S×80`。星级：`C = S` → 3 星级；`C×100 ≥ S×90` → 2 星级；通过 → 1 星级；未通过 → 0 星级。
  （例：5 题对 4 题 = 80% → 1 星级；8 题对 7 题 = 87% → 1 星级；4 题对 3 题 = 75% → 未通过。）
- **只算每题第一次作答**：逐题反馈后再改答案不影响判分（见 §4.1.5）。
- 发星：`awarded = max(0, 本次星级 − 该关历史最佳星级)`，1 个星级 = 1 颗星。首次 3 星级一次拿 3 颗星星；之后从 1 星级提到 3 星级补 2 颗；重玩不提高不发。
- 发碎片：通过时发与**本次星级相同**数量的碎片（1–3 片），同一关每个本地日最多发一次（默认，见 [开放问题](../open-questions.md) Q7），与是否补发星星无关。
- 伙伴经验：本次实际发放的“学习星”每颗给跟随伙伴 +1 经验（见 [companion 需求](companion.md)）。
- 数据库用生成列再算一遍（`attempts.accuracy_pct/stars/passed`），与代码规则不一致时插入失败，保证两处一致。

## 4.1.5 作答（play）：只下发可见部分、逐题反馈、完成一次结算
- **开始**：`POST /levels/:levelId/plays`（请求头带客户端请求 ID）。服务端检查课程开放、关卡解锁、`checkAccess('start')`，在 `plays` 中记录本次下发的题目与选项顺序，返回题目的**孩子可见部分**（题干、选项 ID 与文字/图片、资源 URL），**不含答案与解析**。同一请求 ID 重放返回同一次作答。
- **逐题作答**：`POST /plays/:id/answers {questionId, response}` 返回 `{correct, correctOptionId 或标准答案, explanation}`，客户端据此即时反馈（答对 600 ms 自动下一题，答错停留看解释）。**每题只记录第一次作答**；对同一题再次提交返回第一次的结果，不改判分。跟读题提交 `{done:true|false}`，不返回对错。
- **完成**：`POST /plays/:id/finish`。全部题目都有作答后才可完成（否则 `409 PLAY_INCOMPLETE`）。服务端在一个事务内写闯关记录（`attempts`，每次作答最多一条）、更新最佳星级、写星星与碎片流水、给跟随伙伴加经验、复习入队，并决定本关 3 个藏匿点的内容（见 [discovery 需求](discovery.md)），返回结算结果与藏匿点。重复完成返回第一次的结果。
- 作答默认 2 小时过期（`已默认，可调整`，见开放问题 Q6）；过期后完成返回 `409 PLAY_EXPIRED`，客户端提示“重新开始这一关”。时长用完的宽限见 [controls 需求](controls.md)。
- **版本**：作答固定在开始时的课程版本上；系统管理员在作答过程中发布新版本，不影响这次作答（已发布版本不可修改，旧版本数据永远可用）。下一次开始使用新版本。
- 客户端在内存中保留当前作答 ID；网络失败时重试同一个请求（同一请求 ID），不会重复记录。

## 4.1.6 间隔复习
- 复习条目两类：**义项**（首次通过某关时，该关考查的全部义项进入）和**错题**（任何一次闯关中答错、且没有关联义项的计分题进入，绑定到不可变的题目行；有义项的错题让该义项条目重置到盒 1）。跟读题从不进入。同一孩子同一义项/题目只有一条（唯一键）。
- 复习进度绑定**共享词库的义项**（如 `en.bat.animal`），因此不同课程考到同一个义项共用一条复习条目。
- 盒与间隔：盒 1–6 对应 1、2、4、7、15、30 天。新条目进入盒 1，到期日 = 本地今天 + 1。
- 复习作答：答对 → 盒 +1（最高 6，在 6 盒答对仍为 6），到期日 = 今天 + 新盒间隔；答错 → 回到盒 1，到期日 = 今天 + 1，`lapses + 1`。
- 复习入口显示“今日到期数”= `due_date ≤ 今天` 的条目数。每天最多复习 20 条：`POST /review/plays` 生成一次复习作答，含 `min(到期数, 20 − 今日已复习数)` 条，按 `due_date`、`box`、`id` 升序；超出部分仍保持到期，自然顺延到第二天。
- 义项条目的题目由服务端现场生成：义项有图出“看图选词”，否则出“听音选词”；干扰项从同学科、同年级已发布义项中确定性选出并记录在作答里。错题条目重放原题（不可变题目行）。复习作答同样只下发可见部分、逐题反馈、`POST /plays/:id/finish` 结算。
- 结算时服务端只对“此刻仍到期且属于该孩子”的条目判分（另一台设备已复习过的条目忽略），一次最多 20 条且不超过当日剩余额度。
- **今日复习完成**：某次结算后满足 `今日已复习数 ≥ 20` 或 `剩余到期数 = 0`，且当天开始时有到期条目，则这次记录 `completes_day = 1`（数据库唯一键保证每天最多一次），发 2 颗星与 2 片碎片。当天没有到期条目不算完成、不发奖励。
- 中途退出复习不结算，不留复习记录（未完成的作答过期后清理）。

## 4.1.7 连续学习天数
- “学习日”= 本地日期内**通过至少一关**（任何一次 `passed=1` 的闯关，含重玩）**或完成当日复习**。
- 当前连续天数 = 截至今天（或昨天，若今天尚未学习）的连续学习日数。
- 里程碑：连续段长度达到 3、7、30 天时各发一次：3 天 +3 星、7 天 +7 星、30 天 +20 星；`source_key = streak:{milestone}:{连续段起始日期}`，同一连续段每个里程碑只发一次；断开后重新开始的连续段可再次获得。30 天之后不再有新里程碑。
- 连续天数也是投放规则中“课程设定规则”的一种触发条件（见 [discovery 需求](discovery.md)）。
- 不惩罚断签，不设补签。

## 验收要点
- 开始作答的响应中不含任何答案、可接受答案或解析字段（接口测试 + 数据库 CHECK）。
- 同一题第二次作答不改变判分；重复完成只产生一条闯关记录、一次发星、一次发碎片。
- 作答中途发布新版本，原作答仍可完成并按旧版本判分。
- 两次开始同一关，选项顺序不同（统计测试：20 次中至少出现 2 种顺序）。
