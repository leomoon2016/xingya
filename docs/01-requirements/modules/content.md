职责：共享词库（词、义项）、课程与课程版本、草稿的整个编辑生命周期（表单编辑、自动检查、审核、发布）、题型判分器、课程模板注册（读取仓库中的模板定义）。AI 生成课程草稿由 studio 提供能力、由 content 拥有结果，见 [studio 需求 §4.8](studio.md)。

## 4.1.1 内容结构
- 层级：**年级（1–6）> 课程 > 单元 > 关卡 > 题目**（术语见 [GLOSSARY.md](../../../GLOSSARY.md)）。
  - **课程** = 一册（如“一年级上册”，ID `en-g1-a`；下册 `en-g1-b`），属于一个学科、一个年级、一个模板。**发布与版本以整门课程为单位**：课程版本不可修改，并包含它的全部单元、关卡与题目。
  - **单元** = 课程里围绕一个主题的一组关卡（如 Unit 3 Animals），有跨版本稳定的 `unit_key`（如 `u03`），版本内有序；每个单元 3–6 个关卡（`已默认，可调整`，开放问题 Q26，系统设置 `content.unit_levels`；模板可在此范围内再收窄）。
  - **关卡**：单元内有序，`level_key`（如 `l01`）在单元内唯一、跨版本稳定（不同单元都可以有 `l01`）；每关 5–8 道题目。
- **共享词库**：`words`（拼写形式，稳定 ID 如 `en.apple`）+ `word_senses`（义项，稳定 ID 如 `en.bat.animal`，以词 ID 为前缀）。复习进度绑定义项。词文本与义项释义发布后不可修改（数据库列级授权）；勘误 = 把旧义项退役并新建义项。图片、音标、标准音可以更新。
- 课程 ID、`unit_key`、`level_key`、`question_key` 使用稳定 ID；关卡进度按 `(课程, unit_key, level_key)`、单元进度按 `(课程, unit_key)` 记录，进度与复习跨版本保持。

## 4.1.1a 课程生命周期
| 状态 | 含义 | 谁能改 |
| --- | --- | --- |
| 草稿 `draft` | 系统管理员用表单编辑（不暴露原始 JSON）：增删单元、调整单元与关卡顺序、编辑关卡与题目；可让 AI 生成整门课程或**单个单元**（加入当前草稿）、重写某一题；每次修改后自动检查重新运行 | 系统管理员 |
| 审核中 `in_review` | 自动检查全部通过才可提交；审核人可用“孩子视角试玩”逐关走查（可选，不强制） | 只读；退回则回到草稿 |
| 发布中 `publishing` | 后台任务生成音频（Piper 一次性进程）并把素材复制到公开 CDN 前缀 | 只读 |
| 已发布 `published` | 写入新的课程版本（不可修改），课程当前版本切换到它 | **不可修改**；再编辑 = 基于它新建草稿 |
| 已放弃 `discarded` | 草稿作废 | — |

- 每门课同时最多一份未完成草稿（数据库唯一键）。
- 已发布版本、其单元、关卡、题目与答案对应用账号只允许插入，不允许修改或删除（[roles.sql](../../../db/roles.sql)）。只改一个单元也要发布整门课程的新版本（其余单元原样复制）。
- 正在进行的作答在它开始时的版本上完成；新的作答使用当前版本。
- 课程可整体退役（`retired`）：孩子不再看到，历史记录仍可关联。
- 只有一位系统管理员时，提交人与审核人可以是同一人（`已默认，可调整`，开放问题 Q9）。

## 4.1.1b 题目存储：孩子可见部分与答案部分分开
- `questions.visible`：题干、选项（带选项 ID）、资源 ID——作答前只下发这一部分；数据库 CHECK 拒绝其中出现 `answer`、`accept`、`explanation`、`correct`、`correctOptionId` 字段。
- `question_answers`：正确选项 ID / 标准答案 / 可接受答案 / 正确顺序、解析、答后显示（原文 / 中文 / 例句翻译，`reveal`）。只有判分器在服务端读取，作答后才返回给客户端。
- `learning_cards`：关卡学习卡与单元拓展卡（旧系统，ADR 0020）；属于已发布版本，只追加、不可改，孩子开始作答时随题目可见部分一起下发（学习卡本身没有答案）。

## 4.1.1c 仓库里还保留什么（`seeds/` 内置数据，ADR 0015）
- `seeds/course-templates/`：课程模板定义（每个单元的关卡结构、题型组合、每关题数、适用年级），随发布包部署、api 启动时读取，版本化。
- `seeds/samples/english/grade-1/`：少量示例课程（如 `en-g1-a.json`，含 2 个单元），用 `xingya course:import` 导入为**草稿**（再走审核与发布）。
- `seeds/shop/`（探险徽章初始数据）、`seeds/pets/`（旧系统 24 种宠物，ADR 0021）、`seeds/phrases/`（预设短语/表情）、`seeds/safety/`（聊天过滤词表与 AI 提示词禁止项）、`seeds/avatars/`（孩子头像）。
- 没有课程包、没有构建期音频，部署时不导入课程；部署步骤 `xingya seeds:apply` 只补齐缺失的徽章、种子宠物与默认技能、角色挂载（见 `seeds/README.md`）。
- 旧英语课程不放进 `seeds/`：由一次性命令 `xingya legacy:import-courses` 转成草稿（[studio 需求 §4.8.2](studio.md#482-不变的规则)）。

> 课程文档结构、模板与自动检查规则见 [课程模型](../../03-design/course-model.md)。

## 验收要点
- 已发布题目、答案、关卡、单元、版本：应用账号 UPDATE/DELETE 被拒（数据库验证）。
- 同一版本内 `unit_key` 唯一、单元内 `level_key` 唯一；关卡的单元必须属于同一版本（数据库验证）。
- 单元关卡数不在 `content.unit_levels` 范围内的草稿无法通过自动检查（K13）。
- 修改已发布课程 → 生成新草稿 → 发布后 `version_no + 1`，旧版本数据不变。
- 自动检查未通过的草稿无法提交审核（接口 + 数据库 CHECK）。
