# ADR 0012：呀哈哈由服务器决定，AI 只填写规则表单

- 状态：已接受
- 日期：2026-10-21
- 依据：2026-10-21 设计变更（用户已批准，见 [v1.0 变更记录](../06-releases/v1.0/changes.md)）

## 背景
呀哈哈发现需要随机性、稀有度、库存与每日上限；管理员希望用一句话描述投放规则。若由客户端或 AI 决定结果，容易作弊或失控。

## 决策
- 通关时服务器在同一事务决定 3 个藏匿点的内容（`crypto.randomInt`；有效概率取各适用规则的最大值、上限取最小值、限定款式取交集、保底规则优先），写入 `hiding_spots`；客户端只拿到“点开”结果，放置内容不可改（列级授权），揭晓只能一次。
- 当天序号 `daily_seq` 唯一，并发通关也不会超过每日上限；款式放置数受全站库存 CHECK 约束。
- AI 只把一句话解析成规则表单（`drop_rules.spec`），所有数值受 CHECK 与系统设置范围约束；给管理员确认的规则复述由服务器模板根据表单生成，不使用 AI 原文；规则生效前必须由管理员确认。

## 后果
结果可审计、可复现上限；AI 出错最多导致一条规则被拒或需要修改，不会直接影响孩子。

## 未采用的方案
客户端随机（可作弊）；AI 直接生成可执行规则或代码（不可控）。
