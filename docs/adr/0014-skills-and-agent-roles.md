# ADR 0014：技能（Skill）入库版本化、AI 角色执行、无可执行代码

- 状态：已接受
- 日期：2026-10-21
- 依据：2026-10-21 用户追加的第 10 部分“Skill 管理与 AI 角色”（用户已批准，见 [v1.0 变更记录](../06-releases/v1.0/changes.md)）；扩展 ADR 0009、0012

## 背景
AI 工作室原设计中，课程生成、伙伴设计、款式设计、规则填写各是一个写死在代码里的“处理器”（提示词在代码中）。用户要求：管理员能像管理课程一样管理提示词能力（技能）、按角色组织 AI（课程设计师、美术设计师……与面向孩子的呀哈哈队长）、多角色串联，并保证孩子安全与费用可控。服务器只有 2 GB 内存、单实例。

## 决策
- **技能 = 数据库中的版本化提示词包**（`skills` + `skill_versions`）：何时使用、指令、输入/输出 JSON Schema、内置工具白名单、参考资料、默认参数、推荐模型。每次编辑产生新版本，已保存版本内容不可改（列级授权）；“当前版本”指针提供“跟随最新发布”与回滚。导入导出兼容 SKILL.md 文件夹格式。
- **技能里没有可执行代码**：能力只来自系统内置、由业务模块注册的工具（依赖倒置）；导入包中的脚本只作为惰性文本保存，系统不存在执行它们的代码路径。工具目录中没有发布类工具：AI 只写草稿，发布永远由管理员在界面确认。
- **AI 角色 = 版本化配置**（`agents` + `agent_versions` + `agent_skills`）：挂载技能（固定版本或跟随最新、参数覆盖、优先级）、工具白名单、模型、月度预算、服务对象。技能侧白名单（`skill_allowed_agents`）与受众一致性由复合外键保证；面向孩子/家长的技能与角色发布须单独的儿童安全审核（CHECK）。
- **执行器在 studio 模块中**，管理端运行走 ADR 0009 的 MySQL 任务队列（`ai_jobs.kind = agent_run`）；工具循环最多 20 步，每次模型调用、工具、整次运行都有超时；运行前预估上限，同一事务内预留全站预算与角色预算（`agent_budget_months`，CHECK 兜底）。多角色流水线逐步入队。
- **系统守则在代码仓库中**（`seeds/safety/agent-guard.md`），每次调用都放在所有技能之前，不可关闭；系统技能 `child-safety` 不能停用，儿童角色必须挂载。
- **呀哈哈队长是唯一的儿童角色**：在聊天请求内同步执行（最多 3 步），不写运行记录（数据库禁止儿童受众进入 `agent_runs`），唯一工具只读当前会话孩子的已学词；聊天费用改为计入预算（修订 Q13）。

## 后果
- 提示词与流程可在后台迭代、回滚、试运行，不需发版；原 AI 流程变为“角色 + 技能”，代码只保留工具与确定性系统任务（发布音频、资料抽取）。
- 新增 10 张表（共 65 张）；排期 +1.5 周（约 20.5 周）。
- 部分保证只能由服务层实现（儿童角色必须挂载 `child-safety`、固定的版本必须已发布、角色预算 ≤ 全站上限、参数覆盖键合法），由集成测试覆盖（见[整体评审 · 第十节补充评审](../reviews/2026-10-21-整体评审.md#第十节补充评审)）。
- 提示注入面扩大（导入的技能文本）：通过“导入即草稿 + 审核 + 系统守则 + 工具白名单 + 无发布工具”控制。

## 未采用的方案
- 技能以代码插件形式运行（脚本、MCP 服务器）：在儿童产品和单机上风险与运维成本不可接受。
- 技能存放在仓库、随发版更新：无法满足后台编辑、版本回滚与试运行；仓库只保存默认技能的种子（`seeds/skills/`）。
- 独立的 Agent 框架或服务：额外内存与依赖，单个管理员的工作量用 MySQL 队列足够。
