# ADR 0013：伙伴与呀哈哈动画采用“关键帧图 + 动作模板”

- 状态：已接受
- 日期：2026-10-21
- 依据：2026-10-21 设计变更（用户已批准，见 [v1.0 变更记录](../06-releases/v1.0/changes.md)）

## 背景
伙伴有 4 个成长阶段与多个动作，呀哈哈有大量款式；逐帧 AI 视频生成费用高、风格难统一、文件大。

## 决策
- 每个形象只用 AI 生成少量关键帧图（伙伴每个成长阶段的形象图 + 待机/开心/欢呼关键帧；呀哈哈的弹出/旋转/挥手关键帧），动画由客户端的预设动效模板（如 `idle-breathe`、`happy-bounce`）驱动，模板随前端发布。
- 素材限制：图片 webp ≤ 300 KB（数据库 CHECK）、动画清单（关键帧 + 动效模板参数）≤ 64 KB；“减少动画”设置下只显示静态图；所有素材经审核后才发布到 `pub/`。

## 后果
单个形象的生成费用可预估且较低；风格统一；动作种类受模板限制，新增动作需要发布前端。

## 未采用的方案
AI 逐帧视频或 Lottie 生成（费用与质量不稳定）；纯手绘（单人无法支撑款式数量）。
