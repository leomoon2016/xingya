# ADR 0001：采用模块化单体

- 状态：已接受
- 日期：2026-10-21
- 依据：《星芽学园全新系统设计规格》（已由用户逐节确认）

## 背景
单人开发、单台 2 GB 服务器、首发一个家庭；旧系统的同步桥接与串行 worker 带来全局故障。

## 决策
一个 TypeScript 服务（Node 24 + Fastify 5 + Kysely + Zod + mysql2），分为八个模块（family、content、learning、stars、social、chat、controls、reports），各自拥有自己的表，只通过 `index.ts` 暴露函数；跨模块写入在同一事务内完成；边界由 CI 检查。

## 后果
部署与运维简单，事务一致性容易保证；模块边界需要靠工具守住；将来若要拆服务，可按模块边界拆。

## 未采用的方案
微服务（运维成本过高）；不分模块的单体（边界会腐化）。
